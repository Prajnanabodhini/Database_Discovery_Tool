Purpose

What this project does

The MSSQL Documenter creates a structured map of an approved Microsoft SQL Server database. It lists database objects, reads stored definitions as text, traces possible dependencies, calculates bounded quality statistics, collects masked examples, generates reports, and compares separate runs over time.

It is an observation and documentation tool. It is not a database editor, query workbench, migration tool, backup system, or performance tuner.

Workflow

Why the steps are gradual

1

Prove the guardrails

Dry Run confirms that built-in statements meet the read-only rules without contacting SQL Server.

2

Prove access

Test Connection confirms the approved target, driver, authentication, and basic catalog visibility.

3

Map structure

Metadata creates the lowest-impact real evidence run and exposes missing permissions early.

4

Understand logic

Metadata + Logic statically reads definitions and references; it never calls the code it discovers.

5

Profile carefully

Safe Profile adds bounded metrics and masked examples only after lower-impact stages are understood.

6

Review and hand off

Inspect coverage, limitations, masking, and checksums. Create Git Export only after the independent safety audit passes.

Evidence

Output, Git Export, previews, and raw files

Output evidence
The canonical local result of a discovery run. It contains manifests, catalogues, reports, errors, safety evidence, and checksums.
Git Export
A separately created copy that passes an independent sanitization audit. It is never created automatically.
Formatted preview
A readable Web presentation of a file. Pagination changes only what is visible on one page; it does not change the source.
Open raw
Shows canonical text as stored. Use this when exact delimiters, JSON, SQL, or report source matters.
Download
Retrieves the complete file. Treat output files as local evidence unless they are inside a reviewed Git Export.
Manifest and checksums
The manifest describes the run; SHA-256 checksums help show whether evidence changed after generation.

Safety model

What is protected—and what still needs judgment

  • SQL is validated against a fail-closed SELECT-only policy.
  • Connections use rollback on exit and never enable arbitrary commands.
  • Database names come only from the configured allowlist.
  • Large or unknown-size objects are skipped for value scanning.
  • Credential values are always redacted; other sensitive values are deterministically masked.
  • Git export rechecks evidence instead of trusting labels or checklists.

Important: read-only queries can still consume resources, and heuristic sensitivity detection can be imperfect. Review warnings and classification reports before sharing evidence.

Comparison

How to read Run A, B, and C

Run A is normally the oldest baseline, Run B the next point in time, and optional Run C the newest. The tool reports structural evidence differences. It does not prove why something changed or whether two differently named objects have the same business meaning.

ADDED
Present in the later run but not the earlier run.
REMOVED
Present in the earlier run but not the later run.
CHANGED
The matched identity exists in both runs but compared fields differ.
UNCHANGED
The compared evidence is the same.
NOT AVAILABLE
A run lacks the required evidence.
NOT COMPARABLE
The evidence cannot be aligned safely.

Troubleshooting

Common situations

No databases are listed

Configure either MSSQL_DATABASE or MSSQL_DATABASES in the local .env file, not both, then restart the dashboard.

Test Connection fails

Check the ODBC driver, server name, authentication choice, approved database spelling, encryption settings, network access, and SQL Server permissions. Credentials are never shown in the UI.

A table says SKIPPED_FOR_SAFETY

The table exceeded the configured row threshold, had no trustworthy size estimate, used an unsuitable type, or otherwise could not be profiled safely. Metadata can still be documented.

A run completed with warnings

Open run details, then inspect DISCOVERY_ERRORS.csv, DISCOVERY_COVERAGE.md, and ACCESS_AND_DISCOVERY_LIMITATIONS.md. Do not assume missing evidence means an object does not exist.

Git export is rejected

The independent audit found unsafe, incomplete, unsupported, or already-exported evidence. Keep the output run local, review the job message, correct the cause, and generate a fresh discovery run.

Glossary

Evidence labels

FACT
Directly read from SQL Server catalog metadata or another authoritative run artifact.
DATA_VALIDATION
Computed from controlled data checks, such as row counts or profile statistics.
INFERENCE
A reasoned possibility based on names, shapes, definitions, or patterns. It requires human confirmation.
UNKNOWN
The tool does not have enough reliable evidence to decide.
PII
Personally identifiable information, such as names, addresses, contact details, or identity numbers.
Lineage
Possible movement or transformation of data between objects, inferred from static definitions and dependencies.
Coverage
How much of the requested discovery scope produced evidence, including reasons for gaps.
Sanitized
Processed to remove or mask configured secrets and classified sensitive values according to the safety policy.
